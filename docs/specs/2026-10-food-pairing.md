# 規格：配餐建議

> 一個功能一個檔。設計（ChatGPT Go）、實作（Claude）、驗收（Gemini Pro）都只看這個檔，各自填自己的章節，不改別人的章節。
>
> 狀態：待驗收
> 建立：2026-10-18　最後更新：2026-10-18

---

## 1. 需求（用戶）

- 目的：每支酒顯示「適合配什麼餐／食物」，幫不懂酒的用戶決定開瓶時吃什麼。
- 背景：舊版（2026-10-08 前）曾有配餐標籤，但 AI 從未真正產生配餐資料，畫面一律顯示寫死的「牛扒、煙燻三文魚、陳年芝士」，之後已移除。今次要按每支酒真實產生。
- 使用者：自己酒窖的用戶（手機為主）；查看朋友分享酒窖的訪客只看不產生。
- 範圍內：
  - 新掃描：AI 辨識時一併產生配餐（不另收費、不多扣額度）。
  - 舊酒款（沒有配餐資料）：酒款詳情頁顯示「取得配餐建議」按鈕，按下才用快速模型產生，產生後存入該酒款並跟隨同步。
  - 內容：3 至 4 個食物（中西合璧，香港日常吃得到的中、西、日式食物都可以）＋ 一句淺白書面語原因；中英文各一份。
  - 同一款酒（酒名＋酒廠＋年份）的配餐結果在伺服器快取，其他用戶再取不用再問 AI。
- 範圍外（這次不做）：
  - 按個人口味或飲食限制（素食、過敏）調整。
  - 餐廳推介、食譜。
  - 修改八維中的「配餐價值」分數計法。
- 參考：舊版畫面的 `pairing-pill` 標籤樣式（commit 4cc4f36）。

## 2. 驗收標準（開工前定好，用戶確認後才開始設計）

每一條都要能用「是／否」判斷，並寫明怎樣檢查。

- [ ] AC1：新掃描的酒款，詳情頁顯示 3 至 4 個配餐食物標籤及一句原因。檢查：掃描一支新酒，打開詳情頁。
- [ ] AC2：沒有配餐資料的舊酒款，詳情頁顯示「取得配餐建議」按鈕；按下後顯示載入中，成功後顯示配餐，按鈕消失。檢查：打開一支舊酒款，按按鈕。
- [ ] AC3：取得的配餐會保存：重新整理頁面後仍然顯示；用同一帳號在另一部裝置同步後也看得到。檢查：重新整理；另一部裝置登入查看。
- [ ] AC4：取得配餐建議不會扣 AI 辨識額度；每日有次數上限（訪客 3 ／ 免費 10 ／ Pro 30），用完後顯示「今日次數已用完，請明天再試」，按鈕可再按但不會呼叫 AI。檢查：額度頁數字不變；mock 測試連按超過上限。
- [ ] AC5：同一款酒（酒名＋酒廠＋年份相同）第二次取得時由快取回傳，不計入每日次數。檢查：mock 測試。
- [ ] AC6：AI 失敗或繁忙時顯示清楚的錯誤提示，按鈕回復可按，失敗不計入每日次數。檢查：mock 測試模擬 AI 錯誤及 529 繁忙。
- [ ] AC7：配餐內容中西合璧，包含至少一個中式或亞洲食物（酒款本身不適合配中式時除外，例如甜點酒）；不再出現寫死的預設食物。AI 不確定（例如酒款未能辨識）時顯示「暫無配餐建議」，不可亂作。檢查：抽查 5 支不同類別的酒；搜尋程式碼確認沒有寫死食物清單。
- [ ] AC8：切換英文後，配餐食物及原因全部顯示英文，畫面沒有中文殘留。檢查：英文版 CJK 審計。
- [ ] AC9：中文文案用書面語繁體中文，不含粵語；不使用 emoji 圖示；配色及線條圖示跟現有黑金風格一致。檢查：截圖目視。
- [ ] AC10：查看朋友分享的酒窖時，有配餐資料就顯示，但不顯示「取得配餐建議」按鈕。檢查：用分享連結在無痕視窗打開。
- [ ] AC11：取得配餐只送出酒款屬性（酒名、酒廠、類別、國家、產區、年份），不送相片、帳號、同步碼以外的個人資料。檢查：檢查請求內容。
- [ ] AC12：iPhone 真機（主畫面 App）上配餐區塊顯示正常，不會令詳情頁版面跳動。檢查：用戶真機測試。

## 3. 設計（ChatGPT Go）

> 用戶 2026-10-18 決定今次唔經 ChatGPT Go，由 Claude 沿用詳情頁現有卡片樣式（「評分佐證」卡）設計。

### 3.1 畫面與流程

- 位置：酒款詳情頁「這瓶酒該如何處理？」建議卡之後、「移至酒窖」之前。
- 有配餐：標題「配餐建議」→ 3 至 4 個食物標籤 → 一句原因（金框淺底）→ 小字「AI 建議，僅供參考」。
- AI 判斷唔到：標題 + 「暫無配餐建議」。
- 未有配餐（舊酒款）：標題 + 左邊「尚未有配餐建議」、右邊金框按鈕「取得配餐建議」。按下 → 按鈕變「取得中…」並停用 → 成功後原位換成配餐內容；失敗彈出提示，按鈕回復。
- 訪客（分享酒窖）：有配餐先顯示整張卡，冇按鈕；冇配餐就唔顯示卡。

### 3.2 視覺規格

| 項目 | 值 |
|---|---|
| 主色／輔色／背景／文字（色碼） | 沿用 `.info-block`；標籤邊框 rgba(212,175,55,0.45)、底 rgba(212,175,55,0.06)、字 var(--text)；原因框沿用 `.cr-sum` |
| 字體與字級（標題／內文／小字） | 標題沿用卡片 h3；標籤 13px；原因 12.5px；小字 11px |
| 間距、圓角、陰影 | 標籤間距 6px、圓角 999px、內距 5px 12px；其餘沿用評分佐證卡 |
| 圖示風格 | 無圖示（唔用 emoji） |
| 深色／淺色模式差異 | App 只有深色 |

### 3.3 狀態

| 狀態 | 顯示 |
|---|---|
| 未有資料 | 「尚未有配餐建議」＋「取得配餐建議」按鈕 |
| 載入中 | 按鈕「取得中…」停用 |
| 成功 | 食物標籤＋原因＋「AI 建議，僅供參考」 |
| 冇建議 | 「暫無配餐建議」 |
| 錯誤 | 提示（見 3.4），按鈕回復 |
